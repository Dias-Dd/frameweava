# Point and volume cache playback

Use the R1 named exports `cachedMeshScene`, `cachedPointsScene`, or `cachedVolumeScene` inside `defineNativeStage(init => …)`. See `examples/cache.tsx`: creators supply an asset, topology/material/camera and optional Signal time. Runtime package loading injects the existing admitted GPU and own resource loader. No DOM, Chromium, WASM authorization or filesystem grant is added.

`openPointCache(init,{module:'cloth',format:'mdd'})` loads an **own declared R1 resource module**, validates complete original bytes once, then imports the same sealed file through the existing raw-buffer resource profile. PC2 needs explicit rational source FPS; its start and interval are frame indices. MDD stores Float32 seconds. Coordinates are right-handed Y-up, meters by default; explicitly choose source unit and affine source-to-local transform. Point order is a binding contract, never an inferred vertex ID. Topology is separate MeshData or typed UInt32 `nativeTopology`. No topology-changing caches, automatic retargeting, Alembic or arbitrary JS objects.

`createVolumeCache(init,{samples:[{time,source}],dimensions,bounds})` uses existing `nanovdb-float-indexed-v1` admission, map inversion and sparse-tree lookup. Sources are ordinary sealed project `Resource(kind:'file')`. Supported files are **single raw, uncompressed, breadth-first NanoVDB 32.8 Float fog/SDF grids**, as qualified by the existing profile. This is not an arbitrary `.vdb`, compressed `.nvdb` container, vector grid or blind-payload reader. Convert other formats explicitly with upstream OpenVDB/NanoVDB tools; this library does not launch them in a Stage. Each source may have a different sparse topology/map; resampling uses declared meter world space and explicit target bounds/dimensions. Fog defaults cell centers, SDF vertices. Nearest/trilinear spatial and step/linear temporal interpolation retain background, inactive constants and signed/HDR values. `activity` contains source A/B active weights; `status` zero is valid, bits0–1/2–3 diagnose source A/B coordinate/root-probe failures. A slice displays nonzero status in magenta.

`sample(context,{time,boundary,interpolation})` uses existing FrameContext and Signal evaluation, in seconds; default time is context.time. It never advances solver or Stage time. Clamp is default; error, half-open loop and ping-pong are explicit. Linear point velocity is the segment derivative per source second, with ping-pong sign; zero for clamped/step/turnaround samples. It does not infer the derivative of an arbitrary time Signal. Exact final time uses the left segment; discontinuities have no invented smoothing. F32 GPU interpolation and source-header time precision are explicit numerical boundaries.

Raw positions/velocity/scalar fields remain GPU-resident. Mesh shading reuses the existing area-weighted normal/Gouraud material and Native depth-peel raster. Point rendering uses GPU camera-facing billboards. Fog reuses existing Beer integration; the SDF preview reuses the existing liquid zero-contour surface shader with negated phi and positive-interior absorption. It is a visual preview, not a physical thickness measurement or full PBR renderer. Final images are linear Rec709, HDR RGBA16F/32F, premultiplied alpha; no silent SDR8/CPU pixel fallback. PNG/video conversion is the existing explicit output pipeline.

Sample results and render images are owned by the caller: dispose sample results after their GPU consumers are recorded; release output images through the admitted scope. High-level scenes do this automatically. Logical release does not assert GPU completion: existing owner/session queues and fences own physical lifetime. Immutable point data is initialized once per Stage. Volume source buffers are all admitted at Stage initialization, with the entire sequence included in the configurable byte plan. Core handles sealed snapshots; there is no second LRU. This avoids a demonstrated owner seed-identity failure when frame-local binary imports change size. Streaming source replacement is not qualified on this baseline. Busy, closed, foreign and cancelled uses fail explicitly; dispose is idempotent and never disposes the borrowed GPU owner. Session reconstruction recreates the clip from its seals. No writable simulation/checkpoint state is introduced.

`cache-io.ts` is a **trusted Node-only authoring service**: `inspectPointCacheFile`, `inspectVolumeCacheFile`, and `writePointCache`. The writer streams one frame from an awaited finite XYZ callback, writes MDD/PC2, refuses overwrite, and cleans a uniquely named temporary file on cancellation/failure. It does not make file creation transactionally invisible or implement another Simulation Runner. A callback can explicitly export an existing solver's completed named GPU output. Playback needs no history/checkpoint restoration.

Budgets are configurable (`maxBytes`, `maxWork`, `maxSamples`); actual storage-binding, texture and u32 addressing limits still apply. Whole point-module loading also obeys this baseline's existing SpiderMonkey module-byte admission budget (48 MiB default / 63 MiB ceiling); the newer owner delivery is not silently substituted. Physical peak GPU memory is unknown. Production package/catalog identity, capacity update and L3 portable installation are Main integration work.

Package other reviewed point files with `node --import tsx modules/spatial-creation/scripts/build-cache.ts .frameweave/my-cache --assets=assets.json`. That trusted Node JSON is an array of `{module,file,format,fps?}`; PC2 requires explicit rational fps, MDD rejects it. The default candidate includes two small demonstration resources. Volume source grids remain declared project Resources.

Reproduce the bounded validation campaign using `CREATION_PHASE` with `node modules/spatial-creation/validation/coverage-round13/run.mjs <unique-tag>`: prepare, types/unit, build, real, receipt. Set `CREATION_PACKAGE` to reuse the exact built candidate across later phases. All logs, failed attempts and cumulative wall time remain in `validation/coverage-round13/evidence`. The public shot has 24 frames at 24 fps. Use the ordinary public `frame` and `render` commands shown in that runner's real-stage log.

Sources: existing Frameweave Native GPU/volume/simulation services; Three.js 0.186.1 MIT camera/normal conventions and MDDLoader as independent fixture oracle; OpenVDB 12.1.1 / NanoVDB 32.8 Apache-2.0 traversal/layout and real generated oracle grids. The small bounded MDD/PC2 decoder is original code, avoiding Three's all-frame O(frames²) morph-influence matrix. No GPL source or new runtime dependency is included.
