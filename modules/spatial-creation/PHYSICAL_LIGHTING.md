# Native creator lighting

`litScene(init,{objects,lights,environment,camera})` is an optional ordinary Native Stage factory. `litPlane`, `litBox`, `litSphere`, `groundPlane` and `litObject` consume the existing MeshData/Three topology. Describe objects/materials, camera and animation with existing scalar Signals/keyframes; the scene manages capture, GPU tables and temporary images. See `examples/physical-lighting.tsx`. Previous `studioLighting` and existing creators retain their exact original behavior.

Materials have `ggx` (default), `lambert` and `unlit` models, color/emission/opacity, roughness [.0525,1], metalness [0,1] and explicit cast/receive-shadow flags. Direct GGX reuses the existing Three/MIT single-scatter isotropic D and correlated Smith visibility profile. `sunLight` has an explicit direction toward the source, optional angular radius and fixed deterministic disk quadrature for soft shadows. `pointLight`/`spotLight` use position and inverse-square scene-linear intensity, with an explicit minDistance singularity bound; spot direction points away from its source, inner/outer are half angles. Shadow tests use actual world geometry and light distance; transparent blockers multiply coverage transmittance. Bias is explicit world meters, default .0001. No screen-space fake shadow or CPU pixel fallback.

`constantEnvironment`, `imageEnvironment` and `studioEnvironment` provide actual radiance for cosine-weighted diffuse and GGX-NDF importance-sampled specular integration. Image sources reuse the existing declared Resource/input/provider service. A lat-long image maps +Y to the top pole, longitude atan2(z,x), wraps horizontally and clamps vertically. Rotation is degrees about +Y applied to lookup direction. Samples use a fixed Hammersley sequence, never wall time or render-order noise. Studio is a GPU-generated linear HDR lat-long map with sky/ground and two smooth lobes; it is integrated by the same code as imported images. `samples` is adjustable; no automatic quality or resolution reduction. Optional `occlusion:true` traces those actual environment directions against the same geometry. It is single-scatter IBL, not multiple-bounce GI, PMREM equivalence, caustics or a denoiser.

Environment images must be admitted linear Rec709 RGBA16F/32F opaque or premultiplied radiance. PM texels are explicitly unpremultiplied before bilinear filtering; zero-alpha texels contribute zero. Source alpha does not silently become background opacity. Optional background/backgroundOpacity use the environment separately. Light/material parameters remain HDR scene-linear and final output is premultiplied RGBA16F/32F; existing output services perform PNG/video conversion.

Transparent geometry uses the existing compensated half-open intersection and complete stable distance/triangle ordering, with front-to-back source-over. Layers are never dropped to a fixed count. Opacity models coverage: a tinted veil is not a physically refractive dielectric glass. No volumetric intervals, refraction, absorption through closed solids, spectral transport or automatic material extraction from arbitrary third-party beauty images is claimed.

`createLitRenderer` is the lower-level persistent capture/lighting service: give explicit existing AovSample poses and camera for each request. It does not apply scene-level object controls a second time. `captureLitGeometry` + `renderLitAov` expose the same package's owned AOV geometry for advanced users; one typed lighting response (model/roughness/metalness/shadow flags) is required per triangle, base color/emission/opacity come from that frame. An AOV lease from a separately bundled R1 package is not implicitly interchangeable with this package's ownership coordinator. These APIs accept MeshData and explicit poses, not arbitrary cross-Stage GPU handles or automatic GPU character/cache deformation readback.

Temporary captures/tables/maps retire after their consumers are recorded; output images belong to the caller. High-level scenes handle those lifetimes. The borrowed GPU owner is never disposed. Busy, foreign, closed, cancellation and invalid input are diagnosed; dispose is idempotent. Logical retirement is not GPU queue completion: Core/Renderer owns completion, cancellation, loss and session reconstruction. All time is existing FrameContext; repeated/seek/reopened calls use absolute poses and fixed quadrature, with no new simulation runner or history state.

The conservative work plan includes all geometry/layers and requested shadow/environment samples. maxRayTests (default 1e12 work units)/maxBytes are adjustable; real device/u32/F32 representability limits remain. Geometry scans can be quadratic; there is no real-time or physical peak-memory claim. Legacy MeshData export limits remain. No public P4/Native owner/CLI/permission change. Typed API, machine metadata, raw numerical/media evidence and failure logs are under this module; final catalog/SDK RuntimePin and independent portable distribution belong to Main.

Reproduce with `node modules/spatial-creation/validation/coverage-round14/run.mjs <unique-tag>` (CREATION_PHASE selects prepare, types/unit, build, real, receipt; set CREATION_PACKAGE for the exact built version). Use the public frame/render commands captured in `evidence/campaign.json` and `video-*.json`. Validation covers six independent F64 rectangle cases, HDR sealed Surface-v2 image, direct/soft/transparent shadows, point/spot attenuation, GGX IBL/occlusion, F16/F32 RGB/Alpha/black-white differences, random/repeated/fresh frames and a fully decoded 24-frame one-second creator video. Windows RTX5070Laptop Vulkan only; no cross-platform certification.

Reuse: Three.js0.186.1 MIT camera/topology, original qualified Three dominant-axis ray plus compensated half-open adapter, existing Native single-scatter GGX equations, AOV packing/lifetime, R1 resource and Native GPU services. New glue/quadrature integration is original Apache-2.0 code. No GPL source, additional runtime dependency, new Renderer, GPU owner, resource cache or simulation protocol.
