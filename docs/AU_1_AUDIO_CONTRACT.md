# AU-1 AudioBlock v1, CPU Stage and authoring contract

Audited baseline: `4411d8d` (Main PME + V-SHARED), initially clean `agents/agent-3`. No sync was necessary: Main and this worktree already referenced the same commit. Existing PME owns the professional PCM asset mux; AU-1 reuses it unchanged. Portable contracts, CPU Adapter, Mixer and export service are implemented. Renderer/Session/compiler/package-export wiring is an **isolated, actually executed integration candidate**, awaiting Main's integration of the files it owns. This checkout does not claim that its unpatched public Renderer can run Audio Stages. See `AU_1_DELIVERY.md` and `AU_1_INTEGRATION.md` for evidence and integration boundaries.

## PCM v1

`AudioBlockV1` has kind `audio`, schema `frameweave.audio/1`, interleaved Float32 little-endian samples, explicit 48/96kHz rate and named ordered speaker layout, absolute nonnegative `startSample`, positive `sampleCount`, value ownership, a relative half-open `validRange`, and a CPU-inline **binary Uint8Array** descriptor with exact length. It is a distinct typed port value, never a Json or Surface. Nonfinite values, unknown fields/versions, shared-memory backing stores, inconsistent lengths and oversized blocks fail. Intermediate finite samples above 0 dBFS and negative values are preserved. Maximum block: 262144 samples and 16 MiB.

Supported layouts are mono `[FC]`, stereo `[FL,FR]`, quad `[FL,FR,BL,BR]` and 5.1-back `[FL,FR,FC,LFE,BL,BR]`. Multichannel storage/PCM validation is distinct from spatial DSP: pan v1 explicitly supports only mono/stereo. Arbitrary channel counts do not imply surround support.

WAV accepts little-endian RIFF PCM16, PCM24 and Float32 at supported rates. Multichannel input requires a recognized extensible speaker mask. Output is WAVEFORMATEXTENSIBLE with exact valid bits/mask; Float32 includes a fact chunk and preserves headroom. RF64 and WAV formats beyond this subset are rejected. Integer output requires explicit reject/clip plus none or seeded TPDF dither. Counter-based dither is indexed by absolute sample/channel, so chunk partition/order cannot change quantization. The final quantizer clamps integer code endpoints; Float32 is not forced through integer PCM.

## Time and interval

For rational FPS, frame endpoint `f` maps to `floor(BigInt(f)*sampleRate*fps.den/fps.num)`. Adjacent intervals share the same endpoint. No repeated addition of rounded `dt` occurs. Stage-local offset and global placement are distinct. V1 rejects non-unit rate, reverse and freeze instead of silently resampling. Authored sample callbacks receive absolute sample index, exact-rate seconds and channel; block APIs retain integer interval boundaries.

`AudioStageMetadata` is a pure versioned declaration (schemaVersion 1, sampleRate, layout, durationSamples, seek, lookbehindSamples, lookaheadSamples, latencySamples, tailSamples). V1 implements stateless, zero-lookaround, zero-latency, zero-tail work. Stateful/preroll/restoration and nonzero support fields explicitly fail. No arbitrary previous-block residue may answer random requests. `defineAudioStage(metadata,factory)` exposes the shared authoring marker `Symbol.for('@frameweave/engine.audio-stage')` for Engine/Stage integration; the existing named ESM factory binding must be reused.

The optional `evaluateInterval()` adapter extension shares Renderer execute/DAG/cache/queue ownership in the candidate. Existing frame-only adapters are not automatically audio capable. An explicit request carries both global and local sample intervals plus rational FPS and seed. Output coverage must fully match declared valid samples before downstream consumption. No device handle, DOM AudioBuffer or WASM memory enters the persistent TVG.

## CPU implementation and integration candidate

The next checkpoint adds the actual typed core audio port, optional adapter capability, strict Stage/port gates and an owned CPU `AudioAdapter`. It does not widen PluginPort: P4 visual pipelines explicitly reject audio. Worker inputs/results use structured-cloned binary bytes, not PCM JSON/base64 or PNG. All resources come from compiler-prepared declared assets (32 MiB total for this first in-memory adapter). Each interval gets a fresh factory realm, so no previous request's closure residue can answer a random interval. Stateful processing remains unsupported and rejected when declared; statelessness is an author obligation, not a claim that arbitrary JS mutation can be inferred.

The worker exposes no process/require/fetch/WASM/SharedArrayBuffer, rejects runtime code generation, and has bounded host timeout/termination and output budgets. Pure DSP functions use explicit sample coordinates. This is defense in depth for the existing **trusted local project** execution model; `node:vm` is not an OS sandbox for malicious third-party Node code. Node built-ins cannot be linked into a browser-targeted pure audio bundle. Audio helpers are portable; file/FFmpeg/export functions are separate host-only `audio/node` APIs.

`src/audio/authoring.ts::audioStageSource` is a thin compatibility source helper that calls the existing Stage constructor and uses its existing named-export factory binding. It creates no new Stage node/IR/execution system. FW-1's later ordinary Stage(factory) marker integration can replace this helper at authoring sites. AudioBlock is a runtime media value, never a persistent TVG literal.

`src/audio/layers.ts` consumes the agreed ordinary Layer fields. It samples the **existing** animation evaluator at absolute sample positions using a derived subframe FrameContext; it does not change the integer-only video-frame API or reimplement keyframes/expressions. Gain and group gain are nonnegative; explicit phase inversion belongs in DSP. Mono pan is equal-power, stereo pan is balance with unity center; exact endpoints mute the opposite channel. V1 mixing outputs mono/stereo only; stereo-to-mono and surround mixing require an explicit module. Silence outside placed material is an explicit mixer policy. Requested source intervals must be completely valid; missing source bytes are not silently padded.

Main explicitly assigned Renderer/Session/compiler public wiring to Main/Agent-1. Those working files remain unchanged. `integration/au-1/overlay.ts` copies this worktree's official sources into a new owned validation root and applies exact candidate edits to the **existing** Renderer execute loop/queue/cache and Session queue/seal/lifecycle. Its generated unified diff excludes FW-1 code; FW-1 `7bb3498806ee50f1d0c379800679cc35fa4d91f5` is read-only composed as an explicit prerequisite in that validation root. The candidate consumes its real `layersForMedia` helper. No branch/worktree sync, merge or reset occurs.

The existing PME ProfessionalVideoEncoder is reused unchanged. WAV output supports integer16/24 and Float32; MOV uses explicit final PCM24 quantization, MP4 uses labeled lossy AAC. Pure audio exports WAV without image frames or Chromium; pure-audio MOV/MP4 is rejected rather than fabricating visuals. The host exporter requires reviewed rate/layout/clip/dither settings and refuses non-full frame ranges or a stale expected project hash. Existing source locks/trust remain untouched. Formal public SDK/Renderer availability still requires Main to apply/review the candidate and the final combined SDK pin.

`scripts/verify-au-1.ts` runs real TSX/binary DAG/Layer/WAV/MOV/MP4/Surface/resource/six-export acceptance against the isolated candidate. The first successful eight-case run decoded actual video/audio, compared PCM to independent analytic reference, and loaded each existing export mode while its original project entry was unavailable. It preserved byte hashes of all owned Renderer/Session/compiler/authoring/PCM-mux working files. On Windows, use a short worktree-private FRAMEWEAVE_HOME with the extended path prefix: deeply nested portable cache roots caused an actual Node 22 ENOTCONN pipe failure before this configuration was corrected. The unsuccessful logs are retained and not counted as passing runs.

## Execution and validation order

1. The existing compiler checks local TSX/types, records the named factory and emits a pure CPU bundle. Graph validation checks the new port type, metadata, finite duration and supported time mapping; existing v1/v2 plugin parameter validation is unchanged.
2. The existing Session prepares/seals resources and locks. It snapshots each interval and serializes it through its existing queue. No audio request bypasses package integrity, source invalidation, WASM permission or cancellation.
3. Renderer reuses its DAG pruning, dependency order and Stage cache. The interval request (global/local endpoints, rate, rational FPS, seed), existing time/parameter/input identity and binary content hashes participate in its cache key. CPU binary bytes count towards the existing cache budget. No separate audio cache/scheduler is created.
4. AudioAdapter copies declared inputs/resources into the CPU realm. After authored code returns, bounded binary metadata and PCM are validated, followed by port type, rate/layout and exact sample coverage. Only then can a downstream Stage or Mixer consume the result.
5. Mixer requests source-local samples using the Stage mapping, then places them on the Layer's project sample axis. Gain/Pan and ancestor Gain use the existing Signal evaluator at every project sample. Float64 accumulation is converted to Float32 once at the output boundary; nonfinite/overflow fails.
6. Only final integer PCM conversion performs the explicit clipping/dither policy. WAV writes bounded chunks, while MOV/MP4 reuse PME's existing raw PCM asset mux. Publication refuses overwrite and happens only after encoding and Session close succeed.

Sample intervals are half-open and limited to 262144 samples per request. Coverage is not inferred from byte length alone. A partially valid block can be stored/sliced by the pure library, but an Audio Stage must return the full requested valid interval. The Stage's declared duration and active project interval still apply; a Layer cannot request inaccessible material outside that Stage mapping. No cross-gap interpolation, resampling, reverse playback or hidden preroll occurs.

Layer automation is sample-evaluated. Ordinary `Stage.props` retain the existing Renderer frame-context evaluation contract; AU-1 does not silently turn every video Signal into a sample-domain DSP parameter. For custom sample-accurate DSP, use the request's absolute sample coordinates or an explicit control function inside the authored block processor.

Pure audio uses existing composition timing metadata but generates no Surface, PNG or dummy video frame and launches no Chromium. Visual requests and mixed delivery retain existing Web/PME behavior. Shared frame transactions and sample intervals are intentionally distinct: projects using shared state explicitly fail `E_AUDIO_SHARED_INTERVAL`, pending a separately reviewed audio transaction contract.

## Compatibility and limits

The persistent TVG schemaVersion and P4 ABI are unchanged. The additive `audio` port and `Stage.audio` metadata require an audio-capable engine; old hosts reject the unknown port/backend. Version 1 contracts reject unknown fields and unknown versions. Ordinary JSON audio metadata such as `{kind:'audio',codec:'wav'}` remains legal; the explicit `frameweave.audio/` namespace is reserved for typed media and never accepted as a JSON port.

`audio/index` is portable pure code plus thin Stage authoring. Host I/O/FFmpeg/Session/mux exports are separate in `audio/node`. Existing P4 visual packages cannot declare audio ports: the plan builder returns `E_PLUGIN_IO` instead of changing PluginPort or granting Node rights. Audio third-party package ABI/Registry integration is not implemented; current authoring is trusted local TS/JS with existing named-factory export portability.

V1 does not implement stateful/random-state restoration, lookbehind/lookahead, latency/tail compensation, resampling/time-stretch, surround panning/downmixing, RF64, audio-only MOV/MP4, arbitrary partial-range delivery, real-time devices or compressed streaming inside a Stage. Declared assets are in-memory with a 32 MiB Adapter budget; host WAV input is bounded to 64 MiB and a single decoded compressed block to 262144 samples. Generated long output can stream in bounded blocks, subject to RIFF limits and the existing Session's resource sealing cost. These limits are errors, never silent truncation or invented channels.
