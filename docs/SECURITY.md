# 仅供受信任工程使用

用户库安装保存不可变源码副本；它不授予代码安全认证。发现与搜索只读取元数据，插件仍在原有 Stage 边界中执行。语义模型仅接收本地插件描述，首次下载模型需要网络，离线模式明确禁止补下载。单文件导出的元数据通过 TypeScript AST 读取纯字面量，拒绝路径遍历和超预算，不用 eval 或 node:vm。源码恢复之后仍然是受信任代码构建；导出和安装不是安全审计。`external` 导出策略明确依赖原机器文件；仅对自行审核的工程使用。

P4 插件的信任模型、实际导入图约束、内容/SDK 锁和宿主预算见 [PLUGINS.md](PLUGINS.md)。插件沿用 Stage 级 BrowserContext / opaque iframe 隔离；同一 Stage 内的插件不是彼此敌对的安全边界。当前只适合受信任的本地开发，不能仅凭 JSON 清单校验就托管陌生代码。

这个版本实现了执行环境隔离和受控 Stage 数据交换，但没有建立可托管陌生代码的安全沙箱。不要将它直接暴露为多租户上传/渲染服务。

Web Stage 默认禁止 WASM 编译。显式 `RenderOptions.allowWasm=true` 或 CLI/预览的 `--allow-wasm` 只为 Stage CSP 增加 `wasm-unsafe-eval`；普通 JS eval、opaque iframe、网络和资源白名单不变。该授权不是恶意代码安全认证，详情见 [WASM 执行策略](WASM.md)。

| 已实现 | 实际边界 |
| --- | --- |
| 工程加载独立 Node 子进程 | 15 秒默认超时、256 MB V8 heap；仍以当前用户运行，有该用户的文件和网络权限 |
| 独立 Chromium 进程 | Stage 使用分离的 BrowserContext 和 `sandbox="allow-scripts"` iframe，无 same-origin 权限 |
| 受控交换 | MessageChannel 只传可克隆 JSON 数据；输出在宿主校验；画面以 PNG Surface 交换 |
| 本地资源服务 | 只绑定 127.0.0.1 的随机端口，只提供构建清单中的路径；任意路径和遍历请求拒绝 |
| 浏览器策略 | CSP 限制外部网络、对象嵌入、动态 eval；不提供用户文件或账号会话；Service Worker 禁用 |
| 有界执行 | 每次 Stage 初始化/渲染超时后关闭该上下文；输出尺寸上限 16384，缓存有大小上限；模拟回放有步数上限 |
| 安装控制 | 仅通过根工程锁文件显式安装依赖；加载工程不会自动执行 npm install |

单文件创作不会合并执行环境。`Stage factory={具名导出}` 只是在构建时定位源码入口；浏览器仍在各 Stage 的独立上下文中导入对应模块，Stage 间只交换已声明的数据。函数体不转换成字符串执行，Node 闭包环境及原生对象不进入 JSON TVG，模块私有状态也不在 Stage 间共享。

同一单文件模块会在 Node 构建进程和使用它的各浏览器 Stage 中分别执行顶层代码。需要 DOM/WebGL 的初始化放在工厂内，模块依赖及顶层逻辑必须兼容相应运行环境。这是一项源码组织契约，不是权限限制：具名导出、标准打包和工厂边界仍不能阻止受信任构建代码访问宿主权限。

这些限制不提供 OS 级文件 ACL、容器隔离、完整内存配额或恶意浏览器代码逃逸防御。独立 BrowserContext 也不保证每个 Stage 独占一个 OS 进程。没有使用 `node:vm` 伪装安全边界。

下一阶段应在专用低权限账户或容器中运行构建与编码，挂载只读依赖和按工程授权的资源目录，限制网络、CPU、内存、磁盘与进程数量；限制构建阶段的 Node 内建模块导入，并按依赖白名单分离安装与执行。Linux 可配合 namespaces/seccomp/cgroups，Windows 可采用受限令牌与 Job Objects。该版本只记录设计，不宣称已经部署这些系统级限制。
